# Radial Plots for Matplotlib

This repo teaches you how to build radar charts (also called spider or web charts) in Python
using Matplotlib. Starting from a minimal polar subplot and progressing to a fully custom
polygon-framed projection, you will learn not just how to produce the chart but when it is the
right tool - and when to reach for something else. The repo is structured as a self-contained
notebook with conceptual explanations, worked code, and hands-on concept checks after every section.

---

## Learning Objectives

- Evaluate whether a radar chart is the right visualization for a given dataset and articulate
  concrete reasons when it is not
- Build a basic radar chart using Matplotlib's built-in polar coordinate system with manual
  angle computation
- Register a custom Matplotlib projection (`RadarAxes`) that clips chart content to a polygon
  boundary instead of the default circle
- Control axis orientation, tick labels, fills, and legends on polar axes
- Override Matplotlib internals (`Spine`, `_gen_axes_patch`, `_gen_axes_spines`) to customize
  how a figure's border and clip region are drawn
- Save publication-quality figures to disk with correct bounding-box trimming

## Step-by-Step Walkthrough

### Part 0 - Understanding Radar Charts

Before writing any code, the notebook establishes when a radar chart earns its place and when
it misleads.

Radar charts map each variable to an axis radiating from a center point. All axes share the
same scale and are equally spaced around 360 degrees. Each observation becomes a closed polygon;
the shape of that polygon is the primary signal.

**Why this matters before coding:** The chart's most common misuse is with too many variables
(more than 6) or too many entities (more than 4). With many variables the polygon approaches a
full circle, losing its discriminative value. With many overlapping filled polygons, color alone
cannot separate the shapes. Knowing these limits early prevents you from spending time building
a chart that cannot communicate what you intend.

The notebook also introduces an important perceptual bias: polygon area is a function of both
the data values and the angular spacing between axes. The same dataset produces a different
polygon area depending on the order of the axes - meaning two charts with identical data but
different axis orderings look visually different. The section recommends labeling axis-ordering
logic explicitly when it matters to the audience, or switching to a parallel coordinates plot.

A comparison table at the end of Part 0 maps common situations to better alternatives
(parallel coordinates for many variables, grouped bar chart for precise comparison, line chart
for a single entity over time).

### Part 1 - Basic Radar Chart

**Computing angles**

For N variables, divide a full circle (2*pi radians) into N equal slices:

```
theta_k = k / N * 2 * pi   for k = 0, 1, ..., N-1
```

Each variable gets an axis at an equal angular distance from its neighbors. This is a geometric
requirement - unequal spacing would make some polygon sides appear larger not because the data
values are larger but because the axes are further apart.

**Closing the polygon**

After computing angles, the notebook appends the first angle to the end of the list
(`angles += angles[:1]`) and repeats the same operation for each data row. When `ax.plot()`
connects consecutive points, this forces the line back to the starting vertex, closing the
shape. Without it, the last and first axes leave an open gap.

This is done manually in Part 1 because the built-in polar axes have no automatic close
behavior. Part 2 fixes this by overriding `plot` and `fill` in the custom projection so the
caller never has to think about it.

**Orientation controls**

`ax.set_theta_offset(pi / 2)` rotates the chart so that angle = 0, which normally points right
along the positive x-axis, points straight up instead. This matches the convention most readers
expect for the first axis of a radar chart.

`ax.set_theta_direction(-1)` reverses the angular direction from counterclockwise (the
trigonometric default) to clockwise, so the axes read top-to-right-to-bottom-to-left.

**Why use the basic approach at all?**

The basic polar subplot requires no subclassing or projection registration. It is the right
starting point when a circular frame is acceptable and you want the minimum setup. The trade-off
is that the polygon-closing step is manual and the frame is always circular. Part 2 addresses
both limitations.

### Part 2 - Advanced Radar Chart with Custom Projection

**Why register a custom projection**

Matplotlib's built-in polar axes always draw a circle as the chart boundary. When the desired
boundary is a polygon whose edges align with the axes - a pentagon for 5 variables, a hexagon
for 6 - no built-in parameter can produce this. The only path is to subclass `PolarAxes` and
register the new class so Matplotlib treats it as a named axes type.

After `register_projection(RadarAxes)`, the call `fig.add_subplot(projection="radar")` creates
a `RadarAxes` instance. This is the same mechanism Matplotlib uses internally for its 3D axes
(`projection="3d"`). The name-to-class mapping lives in Matplotlib's projection registry and
is resolved at subplot creation time.

**What `radar_factory` does**

`radar_factory(num_vars, frame)` is a factory function that encapsulates three steps:

1. Angle computation - same as Part 1, plus a pi/2 rotation so the first axis points up.
   The angles are stored in the factory's enclosing scope so the patch functions can reference
   them when building the polygon vertices.

2. Frame shape selection - `draw_poly_patch` returns a `plt.Polygon` built from the axis
   endpoint vertices; `draw_circle_patch` returns a `plt.Circle`. The `frame` argument selects
   which function is bound to `RadarAxes.draw_patch`. This is why the `frame` choice is a
   factory parameter rather than a plot-time parameter - the patch shape is determined when the
   projection class is defined, not when the figure is created.

3. `RadarAxes` definition and registration. Four methods are overridden:

   - `plot` and `fill` delegate to `_close_line`, which appends the first data point to the end
     of every plotted array. This is the same polygon-closing trick from Part 1, but applied
     automatically - the caller never needs to repeat `values += values[:1]`.

   - `_gen_axes_patch` returns the polygon or circle as the axes background. Matplotlib uses
     this patch as the clip region for all drawing inside the axes.

   - `_gen_axes_spines` overrides the visible border. A `Spine` object wraps a `Path` built
     from the polygon vertices. The `Spine` is what clips drawn content to the polygon
     boundary - any line or fill outside the polygon path is hidden. For the circle frame,
     the default `PolarAxes._gen_axes_spines` is used unchanged.

**Why polygon clipping requires the Spine override**

Matplotlib draws chart content first, then clips it to the axes boundary. The clip region is
defined by the spine. The default `PolarAxes` spine is circular. Setting a polygon `Path` as
the spine makes Matplotlib clip everything outside that polygon, which is what produces the
straight-sided radar chart boundary. There is no simpler parameter to achieve this effect.

## Key Concepts Glossary

| Term | Definition |
|------|------------|
| Radar chart | A chart that displays multivariate data on equidistant axes radiating from a center point. Also called a spider chart or web chart. The shape of the plotted polygon is the primary visual signal. |
| Polar axes | A coordinate system where position is given by an angle (theta) and a distance from the center (radius) rather than by x and y coordinates. |
| Theta | The angular coordinate in polar notation. Computed as evenly spaced fractions of 2*pi, one per variable. |
| Polygon close | Appending the first data value (and angle) to the end of a series so that the drawn line connects back to its starting point, forming a closed shape. Required explicitly in the basic approach; applied automatically by the custom projection. |
| `set_theta_offset` | Matplotlib method that rotates the entire polar chart by a fixed angle. Used here to make the first axis point straight up rather than to the right. |
| `set_theta_direction` | Matplotlib method that controls whether angles increase clockwise or counterclockwise. Set to -1 for clockwise to match common reading conventions. |
| `register_projection` | Matplotlib function that maps a string name to an `Axes` subclass. Once registered, the name can be passed as `projection=` to `add_subplot`. |
| `PolarAxes` | Matplotlib's built-in polar coordinate axes class. Subclassed here as `RadarAxes` to add polygon framing. |
| `RadarAxes` | The custom axes class defined in Part 2. Extends `PolarAxes` with automatic polygon-closing, a selectable frame shape, and a polygon spine. |
| Spine | The border line drawn around an axes object. Wraps a `Path` that defines the visible boundary and clip region. Overriding `_gen_axes_spines` with a polygon path is what clips the chart content to a polygon rather than a circle. |
| `_gen_axes_patch` | `Axes` method that returns the background patch used as the clip region. Overridden in `RadarAxes` to return a polygon instead of a circle. |
| Polygon frame | A straight-sided boundary (pentagon, hexagon, etc.) used instead of the default circular clip region. Requires the custom projection to implement. |
| `bbox_inches="tight"` | Argument to `savefig` that trims whitespace around the saved figure by tightening the bounding box to the drawn content. |
| Parallel coordinates | An alternative visualization that represents each variable as a vertical axis with observations drawn as lines crossing all axes. Handles more variables and entities than a radar chart and preserves the ability to spot correlations between adjacent axes. |
| Perceptual area bias | The distortion introduced by radar charts where polygon area depends on axis order, not just data values. The same dataset with axes in a different order produces a visually different polygon area. |
